# GPU-Accelerated Dynamic Pre-Arrival & Revenue Optimization Agent

_Auto-generated by `src/utils/readme_updater.py` on 2026-11-24 15:01 from the files in `metrics/`, `evaluation/`, `validation/` and `outputs/`. Do not edit by hand._

A bounded **LangGraph** state-machine agent for a (synthetic) resort, **Azure Bay Resort & Spa**. Probabilistic reasoning (Qwen3-VL copywriting and intent classification) is strictly separated from deterministic business logic (GPU XGBoost propensity + RMS inventory/margin/discount rules). Every number a guest sees comes from the RMS payload and is verified by a deterministic gate before sending.

## Architecture

### (a) LangGraph state machine with validation gates and retry loops
```mermaid
flowchart TD
    START([Trigger: pre-arrival / inbound reply]) --> N1
    N1["1 enrich_context<br/>PMS + CRM + weather/events"] -->|pre/post validators| N2
    N1 -.->|FAIL_VALIDATION| END1([END: error])
    N2["2 retrieve_knowledge_and_offers<br/>Chroma+BM25 RRF (GPU) + XGBoost (GPU) + RMS rules"] -->|offers found| N3
    N2 -.->|NO_OFFER| END2([END: no send])
    N3["3 draft_message<br/>Qwen3-VL copy with placeholders"] --> N4
    N4{"4 compliance_check<br/>price / discount / SKU / tone / caps"}
    N4 -->|PASS| N5
    N4 -->|"FAIL_POLICY (retry <= MAX_RETRIES)"| N3
    N4 -->|"FAIL_POLICY (retries exhausted)"| N5
    N4 -.->|"FAIL_VALIDATION: opt-out, cap, quiet hours, no inventory"| END3([END: blocked])
    N5{"5 hitl_gate<br/>VIP custom / negative sentiment / repeated failure"}
    N5 -->|no risk| N6
    N5 -->|"interrupt(): ESCALATE_HITL"| Q[(Human concierge queue)]
    Q -->|approve / edit| N6
    Q -.->|reject| END4([END: rejected])
    N6["6 dispatch_and_log<br/>final token re-scan, send, folio booking, audit"] --> END5([SENT / BOOKED])
```

### (c) Two-way guest reply and HITL approval
```mermaid
sequenceDiagram
    participant G as Guest
    participant API as Flask API

    API->>WF: run(inbound_reply)

        WF->>WF: draft confirmation, compliance gate PASS
        WF->>PMS: atomic inventory check + folio posting

    end
```

## UI walkthrough (Streamlit Control Center)
1. **Live Trigger** - choose an upcoming reservation, press *Run pre-arrival workflow*. The offer table shows the RMS price; the message and the guardrail check table appear below.
2. Set *Adversarial test hook* to `once` to inject a fabricated-price draft: the gate rejects it and the retry loop produces a clean one. `persistent` forces escalation.
3. Type a guest reply (e.g. "Yes please, add it to my booking!") and press *Send inbound reply*: inventory is checked live and the item is posted to the folio. Try "This is terrible, I want a refund" for a negative-sentiment escalation.
4. **State Trace** - node-by-node statuses and latencies; repeated draft/compliance pairs are the retry loop.
5. **HITL Queue** - review, edit, approve or reject escalations; approval resumes the paused graph from its SQLite checkpoint.
6. **Data Lineage** - lineage graph, raw table explorer and validation results.
7. **Metrics & Logs** - live metrics from `/api/v1/metrics` plus structured JSONL logs.
8. **Use Cases** - five one-click end-to-end flows (upsell to folio booking, OTA-to-direct loyalty conversion, hallucination blocked then retried, escalation after repeated policy failure, Platinum custom request).

## Sample use cases (end-to-end flows)
In the Streamlit app open the **Use Cases** tab, pick a case and press **Run use case end-to-end**. Each run auto-selects a suitable upcoming reservation and drives the real workflow (also callable via `POST /api/v1/scenarios/<id>/run`, list with `GET /api/v1/scenarios`; definitions in `src/scenarios.py`). The screens below were captured by Playwright from the live UI.

#### 1 · Pre-arrival upsell, guest accepts, folio booking

- **Persona:** Any opted-in guest with a high-propensity ancillary (spa / dining / upgrade / late checkout)
- **Flow:** Agent scores eligible SKUs on GPU, applies RMS price/margin rules, Qwen3-VL drafts warm copy with placeholders, the gate verifies every number, message is sent. The guest replies YES, live inventory is checked and the item is posted to the room folio.
- **Expected outcome:** `SENT, then BOOKED on the folio`
- **Steps:** Pre-arrival offer -> Guest replies YES

#### 2 · OTA guest converted to direct-booking loyalty member

- **Persona:** Booked via an OTA, no loyalty status, offer engine ranks the loyalty offer first
- **Flow:** The highest expected-value action is the free Azure Circle membership (avoids 15-25% OTA commission on the next stay). The offer is a fixed 10% direct-booking benefit supplied by the RMS payload, never invented by the LLM.
- **Expected outcome:** `SENT loyalty offer, guest accepts, membership posted`
- **Steps:** Channel-shift offer -> Guest accepts membership

<img src="outputs/ui_screens/uc2_ota_to_direct.png" width="900" alt="uc2_ota_to_direct">

#### 3 · Hallucinated price is blocked, redraft passes

- **Persona:** Any opted-in guest; the first draft is deliberately poisoned (test hook)
- **Flow:** The first draft claims a fake SKU, a $49 price and 40% off. The deterministic gate finds three token violations (FAIL_POLICY), routes back to draft_message with the violations as feedback, and the second draft passes. The poisoned text never reaches the guest.
- **Expected outcome:** `FAIL_POLICY, retry, PASS, SENT (retries = 1)`
- **Steps:** Offer with poisoned first draft

<img src="outputs/ui_screens/uc3_guardrail_retry.png" width="900" alt="uc3_guardrail_retry">

#### 4 · Repeated policy failure escalates to a human concierge

- **Persona:** Any opted-in guest; every draft is poisoned (test hook)
- **Flow:** Retries are exhausted, so the graph pauses at hitl_gate with interrupt() and a safe fallback draft is queued. The concierge approves and the paused graph resumes from its SQLite checkpoint.
- **Expected outcome:** `ESCALATED, then SENT with the safe fallback draft`
- **Steps:** Offer, every draft poisoned -> Concierge approves safe fallback

<img src="outputs/ui_screens/uc4_policy_escalation.png" width="900" alt="uc4_policy_escalation">

#### 5 · Platinum VIP custom request routed to concierge

- **Persona:** Platinum loyalty guest
- **Flow:** After the offer is sent the guest asks for a bespoke beach dinner. Qwen3-VL plus keyword safety net flags a custom request from a Platinum guest; the agent never improvises, it queues a holding reply for a human.
- **Expected outcome:** `ESCALATED (vip_platinum_custom_request), concierge approves holding reply`
- **Steps:** Pre-arrival offer -> VIP asks for a custom experience -> Concierge approves holding reply
